# 家族アプリ基盤・家計機能 仕様書（DRAFT v2）

> 状態: 設計ドラフト。実装前にレビューして確定する。
> 対象: `officekkobe-beep/family-shopping-list`
> 目的: 現在の買い物リストを1機能として残しつつ、将来さらに機能追加できる「家族アプリ基盤」へ拡張し、その第2機能として家計管理を追加する。

## 1. 全体構成

### 1.1 アプリの考え方
「買い物アプリに家計機能を併記」しない。

共有URLを開くと、まず家族用ホームを表示し、そこから利用する機能を選ぶ。

初期機能:
- 買い物
- 家計

将来:
- 予定
- 家族メモ
- その他の家族用機能

などを追加できる構成にする。

### 1.2 家族用ホーム
ホームでは機能をカード表示する。

例:
- 買い物
- 家計

各カードを押すとそれぞれ独立した画面へ遷移する。

買い物画面では、現行の
- 選ぶ
- かご
- コピー
- 管理
をそのまま維持する。

家計画面は買い物画面とは別UI・別データとして扱う。

## 2. 家計機能の基本思想

家計管理は「毎月必ず入力して月末に締める」方式にしない。

実際の運用に合わせ、費用が発生した期間を積み上げ、任意のタイミングで
1. 確定
2. 精算
する方式とする。

### 2.1 状態
期間の状態は以下。

- 未確定
- 確定・未精算
- 精算済

### 2.2 未確定
費用を入力途中の状態。
何度でも修正できる。

### 2.3 確定
費用入力が終わり、その時点の負担割合を使って
- 2人の本来負担額
- どちらが多く払っているか
- 未精算残高
が確定した状態。

確定後は、その確定範囲の費用・負担割合・計算結果を変更できない。

### 2.4 精算
確定した未精算残高について、実際に入金・送金が行われた状態。

精算された範囲は完全にロックし、以後編集しない。

## 3. 家計トップ画面

家計を開いた最初の画面では「今月」を表示しない。

最優先で見せるのは現在の進捗状況。

表示例:

### 現在の状態
- 最終確定: 2026年10月分まで
- 未確定: 2026年11月分
- 最終精算: 2026年9月確定分まで

### 現在の未精算残高
例:
- あさみ → けんじ
- 42,380円

または
- けんじ → あさみ
- 18,200円

0円なら:
- 未精算残高なし

### 負担状況
現在の未精算対象について
- けんじ実支払額
- あさみ実支払額
- 本来負担額
- 差額
を見せる。

一目で
「今、どちらが負担割合より多く払っているか」
が分かることを最重要とする。

## 4. 未確定期間の表示

家計を開いたときは、最初に「最も古い未確定期間」を表示する。

例:
- 9月まで確定済
- 10月未確定
- 11月未確定

この場合、最初に10月を表示。

未確定がない場合は
- 次に入力する期間
または
- 最新の確定状況
を表示する。

## 5. 予算・上限金額

従来Excelの
`回数 × 10,000円`
方式は廃止する。

今後は設定画面で「上限金額」を直接設定する。

例:
- 月上限 250,000円

上限金額は設定画面から変更可能。

ただし過去確定分は変更しない。
設定変更は指定した適用開始日/開始月以降にのみ適用する。

必要なら期間ごとに別の上限を持てる構造にする。

## 6. 費用入力

「毎月まとめて1回入力」前提にしない。

未確定期間の間は必要に応じて費用を追加・修正できる。

Phase 1の入力単位は1か月とする。

入力:
- 対象月
- けんじ支払額
- あさみ デビット
- あさみ 現金

自動計算:
- あさみ支払合計 = デビット + 現金

ただし設計上は、将来個別明細入力へ拡張できるようにする。

## 7. 負担割合

負担割合は設定画面から変更可能。

例:
- けんじ67%
- あさみ33%

合計100%必須。

### 7.1 変更ルール
未確定期間については変更可能。

ただし、一度「確定」した期間に使用した負担割合は変更不可。

負担割合変更は
「次の未確定期間から新割合を適用」
する。

過去確定分の再計算はしない。

### 7.2 履歴
負担割合は履歴を保持する。

例:
- 2025-04〜: 67 / 33
- 2027-01〜: 60 / 40

確定済期間は当時の割合を固定保存する。

## 8. 計算

期間内の総支出:
```
総支出 = けんじ実支払 + あさみ実支払
```

本来負担額:
```
けんじ本来負担 = 総支出 × けんじ負担率
あさみ本来負担 = 総支出 × あさみ負担率
```

1円未満は四捨五入。

差額:
```
けんじ差額 = けんじ実支払 - けんじ本来負担
あさみ差額 = あさみ実支払 - あさみ本来負担
```

例:
- けんじ差額 +30,000
- あさみ差額 -30,000

なら
```
未精算残高
あさみ → けんじ 30,000円
```

## 9. 確定

未確定期間について「確定する」ボタンを押す。

確定時に保存するもの:
- 対象期間
- 実支払額
- 適用した負担割合
- 本来負担額
- 差額
- 未精算残高
- 上限金額
- 上限との差額
- 確定日時

確定後は編集不可。

誤確定対策として、確定前に確認画面を出す。

例:
「この期間を確定すると、費用と負担割合は変更できません。」

## 10. 精算

確定後、未精算残高は次の確定期間へ累積できる。

精算は任意のタイミングで実施する。
月末・決まった月に限定しない。

例:
- 10月確定後 未精算 20,000円
- 11月確定後 追加 15,000円
- 累計未精算 35,000円

この時点で35,000円を精算してもよい。

### 10.1 精算登録
入力:
- 精算日
- 精算方向
- 精算金額

一部精算に対応する。

- 精算額は未精算残高の範囲内で任意入力
- 一部精算後の残額は未精算残高として継続
- 全額精算時に未精算残高0円

### 10.2 精算済
入金確認後に「精算済みにする」。

精算完了時点までをロック。

## 11. トップ画面の最重要表示

最初の画面は次を優先する。

1. どこまで確定済みか
2. どこまで精算済みか
3. 現在の未精算残高
4. 誰が多く負担しているか
5. 次に処理すべき未確定期間

イメージ:

```
家計

確定状況
10月まで確定済

精算状況
9月確定分まで精算済

現在の未精算残高
あさみ → けんじ
42,380円

現在の負担状況
けんじ  +42,380円 多く負担
あさみ  -42,380円

次に確認する期間
2026年11月
[入力を続ける]
```

## 12. 上限管理

設定された上限金額と確定支出を比較する。

例:
- 上限 250,000円
- 支出 220,000円
- 差額 +30,000円

または
- 上限 250,000円
- 支出 280,000円
- 差額 ▲30,000円

従来のプール残高は残す。
UI名称は「予算繰越残高」を第一候補とする。

計算:
```
当月予算差額 = 上限金額 - 当月支出
予算繰越残高 = 前月予算繰越残高 + 当月予算差額
```

「未精算残高」と「予算繰越残高」は別概念なので、画面上も別カードで表示する。

## 17. 確定済み方針

- 買い物と家計は同一画面に併記しない
- 家族用ホームから機能を選ぶ
- 将来さらに機能追加できる構造
- 最初は未確定の最古期間を優先表示
- 回数入力方式は廃止
- 上限は金額で設定
- 負担割合は変更可能
- 確定後の負担割合・費用は変更不可
- 端数は四捨五入
- 「けんじプール分」は使わず「未精算残高」
- 精算タイミングは自由
- 確定と精算を別状態として管理
- 精算済み範囲は変更不可
- 固定費積立は今回対象外

## 18. 確定済み追加方針

### D-5 対象期間
- 1か月単位とする。
- 月をまたぐ任意期間は扱わない。
- 各月は「未確定 → 確定・未精算 → 精算済」の状態を持つ。

### D-6 精算
- 一部精算に対応する。
- 精算額は現在の未精算残高以下で任意入力できる。
- 一部精算後は残額を未精算残高として繰り越す。
- 全額精算で未精算残高0円となる。
- 精算履歴は削除・上書きではなく履歴として保持する。

### D-7 予算繰越残高
- 従来のプール残高は残す。
- UI名称は「予算繰越残高」を第一候補とする。
- 未精算残高とは別概念として明確に分離する。
- 月ごとの計算:
  - 予算差額 = 上限金額 - 当月支出
  - 予算繰越残高 = 前月予算繰越残高 + 当月予算差額
- 上限超過時は予算繰越残高を減らす。

### D-8 あさみ支払内訳
- あさみ支払は「デビット」と「現金」に分けて入力する。
- あさみ支払合計 = デビット + 現金。
- 精算計算には合計額を使用する。


## 19. 画面設計（スマホ優先）

### 19.1 家族用ホーム
目的: 買い物と家計を混在させず、今後機能追加できる入口にする。

表示:
- タイトル: 家族アプリ
- カード: 買い物
- カード: 家計
- 将来カードを追加できるグリッド構造

操作:
- 買い物 → 現行ShoppingAppへ
- 家計 → 家計トップへ

買い物側の既存下部ナビはそのまま維持する。

### 19.2 家計トップ
目的: いま何をすべきかを1画面で判断できること。

上から順に:
1. 確定状況
   - 例: 2026年10月まで確定済
2. 精算状況
   - 例: 2026年9月確定分まで精算済
3. 未精算残高カード
   - 方向
   - 金額
   - 誰が負担割合より多く払っているか
4. 予算繰越残高カード
5. 次に処理すべき未確定月
   - 最古の未確定月
   - 「入力を続ける」ボタン
6. 精算可能なら「精算する」ボタン
7. 履歴・設定への導線

未精算残高0円の場合は「未精算残高なし」と明示する。

### 19.3 未確定月入力
対象: 最古の未確定月を初期表示。

表示:
- 対象月
- 適用中の負担割合
- 適用中の月上限

入力:
- けんじ支払額
- あさみ デビット
- あさみ 現金

自動表示:
- あさみ支払合計
- 総支出
- けんじ本来負担額
- あさみ本来負担額
- 当月差額
- この月を確定した場合の未精算増減
- 当月予算差額
- 確定後の予算繰越残高見込

操作:
- 一時保存
- 確定内容を確認

「確定する」は直接押さず、必ず確認画面を経由する。

### 19.4 確定確認画面
目的: 誤確定防止。

確認内容:
- 対象月
- けんじ支払額
- あさみ デビット
- あさみ 現金
- 総支出
- 負担割合
- 2人の本来負担額
- 未精算残高への影響
- 月上限
- 予算差額
- 確定後予算繰越残高

注意文:
「確定後、この月の費用・負担割合・計算結果は変更できません。」

操作:
- 戻って修正
- この内容で確定

### 19.5 精算画面
表示:
- 現在の未精算残高
- 精算方向
- 未精算残高が形成された確定月の一覧
- 過去の精算履歴

入力:
- 精算日
- 精算金額

初期値:
- 現在の未精算残高全額

ただし一部精算可。
精算額は現在の未精算残高を超えられない。

精算後表示:
- 今回精算額
- 精算後未精算残高

操作:
- 精算内容を確認
- 精算を登録

精算登録後の履歴は編集・削除不可を基本とする。
誤登録への訂正方法は別途レビュー対象。

### 19.6 履歴画面
月ごとの状態を表示。

例:
- 2026年11月 未確定
- 2026年10月 確定・未精算
- 2026年9月 精算済

月を開くと:
- 実支払
- 負担割合
- 本来負担額
- 当月未精算増減
- 月上限
- 予算差額
- 予算繰越残高
- 確定日時
- 関連する精算履歴

確定済・精算済は閲覧のみ。

### 19.7 設定画面
設定:
- 現在の負担割合
- 月上限金額
- 予算繰越残高の開始残高

変更ルール:
- 確定済月には遡及しない
- 次の未確定月以降へ適用
- 負担割合合計100%必須

設定変更履歴を保持する。

### 19.8 家計内ナビ
家計機能内は以下を基本とする。
- 状況
- 履歴
- 設定

「未確定入力」「精算」は状況画面から行動ボタンで遷移させる。
下部タブを増やしすぎない。

### 19.9 UI優先順位
1. 現在の未精算残高
2. 誰が多く負担しているか
3. どこまで確定済みか
4. どこまで精算済みか
5. 次の未確定月
6. 予算繰越残高

Excelのような一覧性より、スマホでの判断しやすさを優先する。
